# Этап 3 — Контракт внешнего интерфейса (редакция для CLI-агента)

## System

Ты транслируешь код внешних границ системы в контракт. Коды ошибок и форматы
ответов бери только из кода: обработчики исключений, явные возвраты. Не добавляй
«стандартные» коды, которых в коде нет. Аутентификацию определяй по middleware и
декораторам. Отвечай записью файла; содержимое — только валидный YAML.

## User

Репозиторий `{REPO_NAME}`, корень `{REPO_PATH}`.

### Сначала определи, какая граница у системы вообще есть

Найди в коде: маршруты HTTP, обработчики очередей, определения команд CLI,
экспортируемый программный интерфейс. Если HTTP-обработчиков нет — **не выдумывай
OpenAPI**. Запиши это фактом и опиши ту границу, которая есть.

Проверено на живом прогоне: у библиотеки с интерфейсом командной строки не было
ни одного маршрута, и честный контракт получился по 48 командам CLI.

### Куда записать

При наличии HTTP — `{OUT_FILE_OPENAPI}`:
стандартный OpenAPI 3.0 (paths, methods, parameters, requestBody, responses —
только реально возвращаемые коды, security), к каждому path добавь
`x-source: <файл:строка>`.

Если HTTP нет — `{OUT_FILE_CLI}`:

```yaml
openapi_applicable: false
openapi_absence_evidence: <как установлено, что HTTP-границы нет>
interface: cli | library | worker
commands:
  - name: <команда>
    summary: <назначение по документирующей строке кода>
    options: [<опции как объявлены>]
    x-source: <файл:строка>
```

В обоих случаях добавь блок асинхронных взаимодействий:

```yaml
x-events:
  produces:
    - topic_or_queue: <имя>
      payload_schema_ref: <Entity или inline>
      trigger: <когда публикуется>
      source: <файл:строка>
  consumes:
    - topic_or_queue: <имя>
      handler: <функция>
      source: <файл:строка>
x-uncertain: []
```

### Самопроверка

* Пустые `produces`/`consumes` — это утверждение: в `x-uncertain` укажи, по
  каким признакам искал события.
* Если интерфейс расширяется плагинами во время выполнения — отметь, что состав
  у конкретной установки может быть шире объявленного в коде ядра.

## Общие правила вывода (обязательны во всех этапах)

* **Язык артефактов — русский.** Значения полей, обоснования, комментарии и
  сводки пишутся по-русски. Идентификаторы кода, имена файлов и цитаты остаются
  как в исходнике. Смешение языков в одном артефакте недопустимо.
* **Рабочие файлы — не в каталог артефактов.** Вспомогательные скрипты,
  черновики и промежуточные выгрузки клади в `{WS}/_scratch/`. В каталогах
  `inventory/`, `extracts/`, `integration/`, `final/` лежат только артефакты,
  предусмотренные заданием.
* **Цитата кода не сокращается.** `evidence` копируется дословно, подряд, без
  пропуска строк внутри фрагмента и без замены их многоточием. Нужен короткий
  фрагмент — сократи границы цитаты, а не её середину.
