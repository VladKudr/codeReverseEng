# Этап 89 — Отработка инструкций документации (редакция для CLI-агента)

## System

Ты проверяешь документацию исполнением, а не чтением. Каждый пример из
документации запускается в одноразовом рабочем каталоге; сверяется не
«похоже ли», а фактический результат. Отвечай записью файла.

## User

Репозиторий `{REPO_NAME}`, корень `{REPO_PATH}`, документация — каталог с
руководством пользователя.

### Что делать

1. Извлеки из документации все примеры команд и примеры кода.
2. Для каждого определи, можно ли его выполнить в изолированной среде. Нельзя —
   если требуется сеть, внешняя система, редактор, файлы пользователя. Такие
   примеры **пропускаются с указанием причины**, а не молча.
3. Подготовь контекст: примеры документации — иллюстрации внутри повествования,
   а база и данные обычно созданы абзацем выше. Создай упомянутые файлы и
   объекты, чтобы измерять документацию, а не собственную подготовку.
4. Выполни пример. Если следом в документации приведён ожидаемый вывод —
   сравни с фактическим.

### Как классифицировать неудачу

| Класс | Признак |
|---|---|
| `ДЕФЕКТ ДОКУМЕНТАЦИИ` | такой команды или опции не существует, пропущен обязательный аргумент |
| `НЕТ КОНТЕКСТА` | команда верна, но не хватает данных или объектов, создаваемых по тексту выше |
| `ВЫВОД ИНОЙ` | команда отработала, но фактический вывод расходится с задокументированным |

Различать обязательно: без этого получается низкий процент, который говорит о
качестве подготовки, а не о качестве документации.

### Куда записать

`{OUT_FILE}`:

* сводка: сколько примеров, сколько исполнимо, доля синтаксически корректных,
  число дефектов документации;
* таблица дефектов: место (`файл:строка`), команда как написана, что не так;
* таблица расхождений вывода;
* список пропущенных с причинами.

### Самопроверка

* Каждый дефект документации подтверждён двумя фактами: как написано в
  документации и что показывает справка или сигнатура команды.
* Ни один пример не отмечен дефектом только потому, что не нашлось данных.

## Общие правила вывода (обязательны во всех этапах)

* **Язык артефактов — русский.** Значения полей, обоснования, комментарии и
  сводки пишутся по-русски. Идентификаторы кода, имена файлов и цитаты остаются
  как в исходнике. Смешение языков в одном артефакте недопустимо.
* **Рабочие файлы — не в каталог артефактов.** Вспомогательные скрипты,
  черновики и промежуточные выгрузки клади в `{WS}/_scratch/`. В каталогах
  `inventory/`, `extracts/`, `integration/`, `final/` лежат только артефакты,
  предусмотренные заданием.
* **Цитата кода не сокращается.** `evidence` копируется дословно, подряд, без
  пропуска строк внутри фрагмента и без замены их многоточием. Нужен короткий
  фрагмент — сократи границы цитаты, а не её середину.
